## 实盘条件（技术负责人 2026-11-16：回测按实盘的方式算）

候选策略一律用 `run_idea(..., live=LIVE)` 回测（`lab/um_lab.py` 的 `LiveTerms`）：
- 资金 300 USDT（小资金实盘的 `STRATEGY_CAPITAL_USDT`），在策略的固定品种清单上平分，与实盘程序的 1/N 分配相同；
  低于交易所最小下单额的单不发。
  - 注意（2026-11-16 晚更正）：交易所的最小值限制的是订单的名义金额，不是保证金，有杠杆时很小的资金都能下单。
    回测和实盘程序里"单太小发不出"是因为程序定仓位不用杠杆，仓位名义金额不超过分到的那份资金；不是交易所不让下。品种清单要固定：实盘程序只交易规格里列出的品种。
- 每个仓位有交易所 8% 止损（实盘程序的默认值）：K 线内触及就按止损价成交，跳空越过就按开盘价成交，再差 10 个基点，
  收吃单手续费。
- 止损后该品种暂停入场 4 小时，到时自动解除（技术负责人 2026-11-16 选择自动解除、4 小时）。实盘程序也是这样
  （`STOP_PAUSE_SECONDS`），人可以提前解除。
- 收益按整份资金算：没在交易的份额算现金。
- 报告里要写：
  - 实盘下单限额要放到多大：每天最多几笔入场、每天名义额、单笔最大、一小时最多几笔（技术负责人按这个改实盘配置）；
  - 试运行硬止损会触发几次：90 天的试运行里有多大比例会亏到 15% 被叫停（`loss_stop_share`）、日亏 3% 的天数（按日收盘算，盘中触发会更多）。报告里的 `losing_streak_stops` 是已经取消的旧停止规则的次数，只作参考。
- 还没模拟的实盘差别：
  - 回撤锁定和 3 倍敞口按整个账户算（技术负责人的选择；账户大时很少触发）；
  - 每品种按自己的盈亏复利，实盘是共用一份资金（差别是二阶的）；
  - 小币种的买卖价差按统一的 3 个基点估计。

## 评审员怎么跑（`lab/um_judge.py`，2026-11-16 起）

第一轮的流程写在一次性脚本 `runs/2026-11-16/judge.py` 里，没有测试；它留作那一轮的记录。从下一轮起，流程在
`lab/um_judge.py`（有测试，`tests/unit/lab/test_um_judge*.py`），每晚的 `runs/<日期>/judge.py` 只把当晚的想法交给它：

```python
from lab import um_judge as judge, um_lab as lab
import ideas as lib                    # 当晚的 ideas.py：IDEAS = {名字: (函数, 参数表)}，XS = 横截面想法的名字

dates = [start for start, _ in judge.PERIODS]
lists = judge.universe(lab.SNAPSHOT, dates, capital=lab.LIVE.capital, slots=10)   # 连同规则写进 universe.json
j = judge.Judge(ideas=lab.lab_ideas(), lists=lists, cache=Path("/tmp/lab_<日期>"), run_date="<日期>",
                lookahead=causal)              # causal：当晚脚本里的防未来函数检查
# R7c：想法要写成 trading/domain/strategy 里的策略（实盘跑的就是这份代码）；还没写成策略的研究函数用
# lab.legacy(函数, cross=是否横截面) 包一下也能回测，但不能上实盘
screened = j.screen(variants=judge.STOP_VARIANTS)   # 挑选窗口的全部配置、滚动前推、打分、淘汰；不读验证段
checked = j.final(screened)                         # 只对过淘汰线的想法打开验证段；冠军或 None
```

工具里固定下来的规则（做法仍以 `runs/2026-11-16/ideas.md` 的"回测的做法"为准）：

- 时段 `judge.PERIODS`：第一段只用来挑选，中间三段是滚动前推的三折，最后一段是验证段。
- 品种清单 `universe`：每段开始前 30 天日成交额中位数最高的 N 个，至少有 25 天数据，一笔最小的单不超过一份资金的三分之二，
  去掉稳定币合约；只用那个日期之前的 K 线。
- 一个配置 = 想法的一组参数 + 止损方案 `StopVariant`（止损距离；止损后暂停几小时，或 `signal_reset`：等目标仓位回到 0
  再出现信号才入场）。`STOP_VARIANTS` 是 `runs/2026-11-17/plan.md` 的 12 种，实盘的 8% 加 4 小时排第一。
  每一折用它之前的数据里夏普最高的配置，参数和止损方案一起选；夏普相同时先比参数的文字（第一轮的规则），再取排在前面的方案。
- 每段开始时每个品种从一份资金重新开始。日收益按 UTC 自然日算，从这一份资金算到这一段最后一根 K 线收盘，
  所以相邻两段首尾相接，不重不漏。
- 淘汰线、打分表、最终检查照 `ideas.md`；没有给 `lookahead` 检查的，"防未来函数"一项算不通过。
- 验证段只在 `final` 里读，而且只读过了淘汰线的想法；`run_all` 默认拒绝验证段的任务。
- 每个配置每一段的结果先登记到 `research/lab/trials.jsonl`（写明止损方案），再进缓存（JSON；设置不同的缓存会被拒绝）。

和第一轮脚本不同的地方：

- **每段的第一天**：第一轮的脚本把每段第一天的收益（含重新开仓的成本）漏掉了，一天还是按 23:00 截的，
  所以它的滚动前推是 909 天，而持有 BTC 是 912 天。工具默认把每一天都算上；`legacy_days=True` 只用来复现第一轮的数字
  （`runs/2026-11-16/reproduce.py`，结果在 `reproduction.json`）。
- 打分表的两个边界照表上写的算：最大回撤正好 15% 得 4 分（表上 5 分是"< 15%"），熊市和震荡都正好赚 5% 得 5 分（"5% 以上"）。
  第一轮脚本在这两个点上分别给 5 分和 4 分；实际数字不会正好落在边界上。
- 登记在算完一个配置后立刻写，不等全部算完。

## 打分（1–5 分，每项）

扣成本后的滚动前推收益、最大回撤、交易笔数、最长连亏、熊市和震荡期的表现。

**扣成本后跑不赢买入持有的，不交易。**

## 加冕冠军前的最终检查（每张卡都要回答）

1. 在没见过的数据上还赢吗？
2. 扣了手续费和资金费还赢吗？
3. 至少 50 笔交易吗？
4. 手续费翻倍还成立吗？
5. 参数换成邻近值还成立吗，还是只靠一个幸运值？
6. 有没有数字从未来泄漏？用 `lab/causality.py` 的检查。
7. 按实盘条件（300 USDT、8% 止损、止损后暂停）还成立吗？需要多大的下单限额？试运行硬止损多久触发一次？

每张卡以 **WHY THIS COULD FAIL** 结尾。宁选平淡可靠的，不选刺激侥幸的。实验室的冠军一律标为"未验证"：同一批数据上挑出来的最好者，带着挑选偏差。

## 策略卡

- 一句话想法；为什么有优势、谁在付钱。
- 精确的入场、出场、止损规则；每笔的仓位。
- 扣成本后的结果对比买入持有；滚动前推结果。
- 最差的月份；最长连亏。
- 实盘条件下的结果、需要的下单限额、硬止损触发次数。
- 杀死它的市场条件；它开始失效的第一个迹象。

## 规则

- 只用有来源、有时间戳的真实数据。绝不编造价格、成交、回测数字或盈利；估计一律标"估计"。
- 每个测过的配置都登记到 `research/lab/trials.jsonl`：日期、想法、参数、窗口、结果。多重检验按整组扣减。
- API Key 只开交易、不开提现，绝不进代码或聊天；实验室不碰交易所账户。
- 过线的想法先冻结规则，在新数据上跟踪 4 周：每周登记一次查看（`research/forward_looks.jsonl`，照前向检验协议的做法），每次用新下载的快照重跑；四次都成立才进小资金实盘试运行（技术负责人 2026-11-16 晚）。这不是模拟盘，不部署任何东西。
- 不做模拟盘和测试网（技术负责人 2026-11-16）。上小资金实盘之前要满足：技术负责人亲自把签名规格标为"已通过"（代码从不改它）、账户里没有程序账本以外的仓位、告警文件（`ALERT_FILE`）和心跳配好、主机装好、有策略资金上限；真钱要等技术负责人说"go live"。
- 卡住时留一个问题给技术负责人，然后继续。
