# ADR-0005：急停、平仓与止损的语义

- 状态：提议，待批准
- 日期：2026-11-14
- **本决策改变风控行为。每个子项都需要您单独确认，未确认的子项保持现状。**

## 背景

候选运行时的入场侧有六道门，任何未知状态都阻断。退出侧有 7 个高风险缺口（`docs/arch/current-state.md` R1–R7），其中 4 个已用探针复现：

| 编号 | 现象 | 证据 |
|---|---|---|
| R1 | 平仓单被拒或超时后，同一小时内不再重试 | `runner/binance_target.py:152,212`；`execution_adapter.py:144-145`；探针场景 a |
| R2 | 有挂单时 kill 平仓被跳过；入场挂单不被撤销，在 kill 期间继续成交 | `runner/binance_target.py:209`；探针场景 e |
| R3 | 止损挂不上时只记一条 issue，仍允许入场 | `protective_stops.py:129-136`；探针 C 段 |
| R4 | 平仓和止损按本地账本定量；账本为 0 时不处理交易所上的真实仓位 | `runner/binance_target.py:208-209`；`protective_stops.py:73-78,112-113` |
| R5 | 急停命令行默认路径不是运行时读取的路径；文件缺失即未激活 | `shared/kill_file.py:25,41-42`；`runner/binance_target.py:258,373` |
| R7 | 减仓被订单库状态拒绝时不写日志 | `shared/confirmed_execution.py:120-140` |

现有原则"同一意图至多发一次、超时只查不重发"是正确的，下面的方案都不违反它：重试用的是新的意图 id，并且只在上一次尝试已经结算之后才发。

## 子决策 1：平仓失败后的重试（R1）

- **1a 现状**：等下一根小时 K 线，id 才变。
- **1b 有上限的重试（建议）**：平仓意图的 id 带尝试序号。上一次尝试结算为未成交终态（`rejected`、`not_found`、`canceled`、`expired`）后，间隔 30 秒发下一次；连续 10 次失败后停止自动重试、持续告警，之后每根 K 线再试一次。
- **1c 无限重试直到平掉**：不设上限。

取舍：重试的风险是重复下减仓单。减仓单是 reduce-only，数量不超过交易所持仓，重复的最坏结果是被交易所拒绝。不重试的风险是敞口原样暴露最长一小时。1c 在交易所持续拒单时会无限刷请求，可能触发限频封禁，所以不建议。

间隔和次数是新增的参数，数值请您定。

## 子决策 2：急停时挂着的入场单（R2）

- **2a 现状**：不撤，等它到期；期间不平仓。
- **2b 先撤后平（建议）**：kill（平仓）或回撤闩锁激活后，第一步撤销该品种全部入场挂单，第二步平仓。撤单结果不明时仍然继续平仓（平仓前会重新读交易所持仓）。

取舍：2b 的代价是撤单与成交竞争时，平仓数量要以撤单后的交易所持仓为准，逻辑比现在多一步查询。

## 子决策 3：急停平仓按什么定量（R4）

- **3a 现状**：取 `min(交易所持仓, 本策略已确认账本)`；账本为 0 或方向相反时不动作。
- **3b 急停路径按交易所持仓全平（建议，有前提）**：kill（平仓）和回撤闩锁触发的平仓，直接按交易所上该品种的实际持仓全平。策略自身的再平衡减仓仍按 3a。
- **3c 两者不一致时不动作并告警**：把处置完全交给人。

取舍：3b 的前提是这个账户上这两个品种只有本运行时在交易。如果账户上还有人工仓位或其他程序的仓位，3b 会把它们一起平掉。3a 在账本落后于交易所时（成交历史查询失败、止损成交未入账）会漏平。

**需要您回答**：交易账户是否专用于这个运行时。如果不是，建议 3c。

## 子决策 4：止损挂不上时怎么办（R3）

- **4a 现状**：记录 issue，继续运行，入场不受影响。
- **4b 阻断入场并告警（建议）**：有持仓但没有有效的交易所侧止损时，入场就绪标志为假，并发出告警。已有持仓不动。
- **4c 立即市价平仓**：没有止损保护就不持仓。
- **4d 自动写入 kill 文件**：不建议，运行时不应改写操作员的文件（见子决策 6）。

取舍：4c 最保守，但止损接口临时故障会导致策略被动清仓，换手和成本上升。4b 保留现有仓位，把是否平仓交给人判断。

## 子决策 5：kill 文件缺失的含义与路径（R5）

- **5a 现状**：文件不存在即未激活；命令行默认路径指向 `binance_main` 的目录。
- **5b 路径单一来源，执行模式要求文件存在（建议）**：命令行和运行时用同一个函数从状态目录解析路径，命令行必须给出状态目录，没有默认值。执行模式启动时要求 kill 文件存在且可读（内容可以是未激活）；运行中文件消失按激活处理。
- **5c 只修路径，缺失语义不变**。

取舍：5b 让"文件不存在"不再等于"安全"，与其他状态的失败即阻断一致，代价是首次启动前要多执行一次初始化命令。纸面模式不受影响。

## 子决策 6：运行时能否改写 kill 文件

- **6a 现状**：`binance_main` 在退出重试耗尽后把文件写成 `flatten=False`（`runner/binance_main.py:466-469`）。`binance_target` 不写。
- **6b 运行时只读（建议）**：`KillSwitch` 端口只有读方法，写方法只在命令行里。重试耗尽通过告警和状态文件表达。

## 子决策 7：减仓被拒绝预留时的可观测性（R7）

- **7a 现状**：返回空，不写日志。
- **7b 写事件日志并告警（建议）**：拒绝原因（已有未结减仓、有未消费成交、检查点版本不符）写入事件日志；连续被拒超过一定时间告警。拒绝规则本身不变。

是否为急停平仓开一条绕过这些拒绝规则的通道，取决于子决策 3：选 3b 时，急停平仓按交易所持仓定量，不依赖检查点版本，自然不受"检查点版本不符"的限制；"已有未结减仓"的限制保留，以防重复平仓。

## 不在本决策内

以下是风控参数或其语义，本次迁移不改，只记录：

- 回撤阈值没有硬上限；三个运行时的默认值不同（3/10、3/8、5/12）。
- 回撤闩锁在 UTC 日 / ISO 周边界自动解除；没有累计回撤上限。
- 交易所杠杆设置上限是 10，高于 3 倍敞口上限。
- 敞口上限只在入场时检查，持仓期间没有持续监控。
- 止损触发并入账后没有冷却，下一根 K 线目标不变就会重新入场。【推测】未运行验证。

如果您希望调整其中任何一项，请单独提出。

## 后果

- 探针里的缺陷场景会先作为特征化测试固定现状，批准后改成断言新行为的测试。
- 新增 `Notifier` 端口的实际使用点。资金路径上现在没有任何告警调用。
- 文档 `docs/binance_runbook.md` 的急停章节要跟着改。
