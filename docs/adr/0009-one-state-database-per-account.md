# ADR-0009：每个账户的状态放在一个带版本号的数据库里

- 状态：**方向已决定**（技术负责人，2026-11-15："M5 之前合并"）。下面的设计细节在实施时如有变动，在本文更正并记入 `execution-log.md`。
- 日期：2026-11-15

## 背景

【代码】一个执行模式的状态目录里有 5 个 SQLite 文件：

| 文件 | 表 | 写入者 |
|---|---|---|
| `orders.sqlite` | submissions、execution_fills、execution_consumers、manual_actions、protective_stops | 订单库 |
| `drawdown.sqlite` | drawdown_periods、equity_observations | 回撤锁定 |
| `order_limits.sqlite` | order_limits | 限额计数 |
| `entry_pauses.sqlite` | entry_pauses、pause_triggers | 入场暂停 |
| `paper_state.sqlite` | paper_state、paper_state_archive | 模拟盘 |

由此带来的问题：

- **没有跨文件事务。** 止损触发记在订单库，入场暂停记在暂停库。为了不因"暂停没写成"而放行，第 12b 步之后加了"由止损记录推导暂停，并记录哪些触发已被覆盖"的机制。
- **每个文件都可能单独丢失或被清空。** M3 之后审计的 3 条中危发现都属于这一类。现在靠启动检查逐个核对文件和表来补。
- **建表时机不一致。** 有的存储每次读写都建表，有的只在构造时建表（M3 审计后改的）。
- **没有版本号**，将来改表结构没有迁移的办法。
- **连接设置不一致。** 订单库用 WAL 模式加完全同步，其余用 SQLite 默认设置。

## 决定

1. **每个执行模式的状态目录只有一个数据库文件 `state.sqlite`**，放上面除模拟盘以外的 10 张表。
   - 急停文件仍是独立的 JSON：它由人的命令写入，不依赖 SQLite 也要能读。
   - 清单 `manifest.json` 和执行租约的锁文件也保持不变。
   - 模拟盘现在不要求初始化目录，它的状态和 JSON 镜像先保持原样。方案 B 让模拟盘也走订单库等执行路径之后，模拟盘目录同样改为初始化后使用同一个 `state.sqlite`，届时在本文更新。
2. **一处统一的连接设置**（`trading/adapters/sqlite/` 里的一个连接工厂）：WAL 模式、`synchronous=FULL`、统一的忙等待时长。各存储共用它。
3. **版本号**：`PRAGMA user_version`，第一版为 1。
   - 只有 `state_dir init` 建表、写版本号。
   - 运行时的各存储从不建表，只打开已有的数据库文件（M3 审计后限额存储的做法推广到全部存储）。
4. **启动检查**：清单、账户身份、版本号、全部 10 张表、急停文件，有一项不对就拒绝启动。
5. **迁移**：由人执行，运行时必须停止，并且先备份；从不自动执行。
   - 现在没有任何执行模式的状态目录在用，模拟盘也没有部署，所以第一版**不迁移旧的 5 文件布局**。
   - 遇到旧布局时拒绝启动，并提示"初始化一个新目录"。
   - 以后改表结构时，再加 `state_dir migrate`。
6. **跨存储事务**：合并之后，相关写入可以放进同一个事务。第一步先只合并文件，不改各存储的行为。之后在确有好处的地方（例如止损触发与入场暂停）再用同一事务，届时另行记录。

## 备选方案

- **维持 5 个文件，只补版本号和统一建表时机。** 成本最低，但"单个文件丢失"和"没有跨文件事务"这两类问题仍在。
- **换成服务器型数据库。** 对单进程、每小时一次决策的运行时来说过重，还会引入网络这个新的故障点。

## 后果

- 备份和恢复只涉及一个数据库文件加一个急停文件，M5 重做的备份因此变简单。
- 所有存储适配器的构造方式都要改：从"各自的文件路径"改为"共用的数据库"。
  - 测试里大量直接用临时路径构造存储的地方，需要改设置。
  - 这些改动只涉及设置，并会记录。
- 架构规则"只有 SQLite 适配器使用 `sqlite3`"不变。连接工厂也在 SQLite 适配器里。

## 验收

- `init` 只建一个 `state.sqlite`，版本号为 1，10 张表齐全。
- 版本号不对、少表、旧的 5 文件布局，都拒绝启动，而且不创建任何文件。
- 运行中数据库被删除或清空：读写失败，不重建；入场被阻断，平仓照常执行。
- 现有的运行时测试、研究模拟指纹测试、模拟盘与研究逐笔一致的测试，断言不变并全部通过。
