# ADR-0001：迁移范围与新旧边界

- 状态：提议，待批准
- 日期：2026-11-14

## 背景

仓库里有两个系统（`docs/arch/current-state.md` 第 7 节）：

- 2026-03 为主写成的 ML 系统和多交易所运行时，约 8 万行 Python 加 3.5 万行 Rust，策略线已关闭。
- 2026-11 写成的目标仓位运行时，资金路径约 3,000 行，是唯一候选。

后者通过三处耦合依赖前者：`runner/binance_target.py` 从 `runner/binance_main.py` 取 6 个符号；`execution` 包的 `__init__` 急切导入 Bybit 适配器和未接线的 bridge；`lab/orders.py` 经 `event` 包依赖 Rust 扩展。

约束：每个改动少于 400 行，系统始终可运行，禁止大爆炸式重写。

## 备选方案

### A. 新建 `trading/` 包，只迁候选运行时（建议）

- 四层结构只建在 `trading/` 里。把候选运行时用到的代码逐块移入，旧位置留只做重导出的薄壳，直到没有引用再删。
- 遗留代码原地不动，由 import-linter 契约保证 `trading/` 不 import 它们。
- 优点：改动面小（约 3,000 行，而不是 8 万行）；每一步都能单独回滚；新包从第一天起就能加严格的架构规则。
- 缺点：迁移期间新旧两种组织方式并存；薄壳会存在一段时间；遗留代码的问题原样留着，直到 ADR-0008 决定去留。

### B. 原地重组整个仓库

- 把现有 19 个顶层包全部按 domain / application / adapters / infrastructure 重新归位。
- 优点：结束后只有一种组织方式。
- 缺点：要搬动 456 个模块，其中一半不在任何运行路径上，一半属于已关闭的策略线。无法拆成少于 400 行的改动。12 个包处于同一个循环依赖组里，中间状态很难保持可运行。

### C. 新仓库，只带走候选运行时

- 优点：最干净；没有遗留代码的干扰。
- 缺点：失去 git 历史与现有 2,920 个测试的保护；研究代码（`lab/`、数据快照、试验登记）需要两边同步；正在进行的前向纸面运行要换部署。这等于一次大爆炸式切换。

## 建议

采用 A。

## 后果

- 新增顶层包 `trading/`，需要加进 `pyproject.toml` 的打包清单和 `Dockerfile` 的复制步骤。
- `runner/binance_target.py`、`lab/strategy.py` 等旧路径在迁移期间继续可用，systemd 单元不用改。
- 遗留代码的测试继续跑，不删。
- B 中"整个仓库只有一种组织方式"的目标，在 ADR-0008 的分批删除完成后自然达成。

## 需要您确认

1. 是否同意只迁候选运行时，ML 线与其他交易所原地冻结。
2. 新包名 `trading` 是否可以。
