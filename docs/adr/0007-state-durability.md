# ADR-0007：状态持久化与启动自检

- 状态：提议，待批准
- 日期：2026-11-14
- 子决策 2、3、4 改变运行时行为，需要您确认。

## 背景

候选运行时的状态分布【代码】：

| 状态 | 存在哪 | 重启后 |
|---|---|---|
| 订单意图、成交、持仓检查点 | `orders.sqlite`（`shared/execution_journal.py`） | 恢复 |
| 回撤高水位与闩锁 | `drawdown.sqlite`（`shared/drawdown_guard.py`） | 恢复 |
| 下单日限额计数 | Rust 对象的进程内存（`risk/rust/order_limiter.inc.rs`） | 清零 |
| 纸面持仓与权益 | `Sleeve` 的进程内存（`runner/binance_target.py:104-105`） | 归零 |
| 待确认订单集合 `pending` | 进程内存（`:119`） | 清空 |
| K 线窗口、资金费 | 进程内存 | 预热时重新拉取 |

问题：

- **R6**：订单库和回撤库的构造函数是"不存在就建"。目录被清理、`--state-dir` 写错、工作目录不同或 `RISK_SCOPE` 改名后，回撤闩锁静默消失。【实际运行结果】已复现。
- **R12**：日限额重启清零。
- **R10**：行情请求失败一次进程即退出；systemd 60 秒后重启；纸面状态归零，前向纸面记录不连续。

旧运行时有一套"受管状态目录"（`shared/runtime_state.py`）：显式初始化、带清单和账户身份、缺库拒绝启动。它不覆盖 Binance 运行时。

## 子决策 1：状态目录是否受管

- **1a 现状**：自动创建。
- **1b 复用 `shared/runtime_state.py`**：它已有测试，也有配套的备份与迁移工具（共 933 行）。缺点是它与 Bybit 钱包账本、组合额度库绑在一起，带进来等于让新包依赖冻结线的概念。
- **1c 为新运行时写一个小的清单机制（建议）**：状态目录里有 `manifest.json`，记录 scope、创建时间、库结构版本。一个显式的初始化命令创建目录、清单和空库。执行模式启动时，清单或任何一个库不存在、scope 不符、库不可读，都拒绝启动。纸面模式缺失时可以自动初始化。

取舍：1c 约 150 行，功能比 1b 少（没有备份和迁移工具）。备份可以先用 SQLite 自带的 backup 命令加停机流程，写进运行手册。

## 子决策 2：日限额计数持久化

- **2a 现状**：进程内存；"日"是进程启动后的滚动 86,400 秒。
- **2b 落盘，按 UTC 自然日计（建议）**：计数存进 SQLite，键是 scope 加 UTC 日期，与回撤闩锁的周期口径一致。

这改变了"日"的定义，但不改限额数值。按 UTC 日计时，跨零点会清零；按滚动窗口计时不会。两种口径在边界上允许的下单量不同。

## 子决策 3：纸面状态持久化

- **3a 现状**：重启归零。
- **3b 每根 K 线后落盘，启动时恢复（建议）**：模拟账户的持仓、权益、挂单存进 SQLite。启动时如果最后处理的 K 线与当前游标之间有缺口，按缺口里的 K 线补算，补不齐则拒绝继续并告警。
- **3c 启动时从事件日志重放**：不新增存储，从 `events.jsonl` 重建。缺点是事件日志现在只是观测输出，没有完整性保证。

## 子决策 4：行情请求失败时是否退出进程

- **4a 现状**：异常穿透主循环，进程退出，由 systemd 重启。
- **4b 捕获并退避重试，期间入场保持阻断（建议）**：行情请求失败时本轮跳过行情步骤，对账、止损维护、kill 平仓照常执行。连续失败超过阈值告警。已有的"K 线处理过晚则不入场"规则（`runner/binance_target.py:181-182`）保证不会用过期数据开仓。
- **4c 保持退出，但把对账和风险动作移到预热之前**：重启后先处理退出侧，再拉行情。

取舍：4a 的问题是行情接口不可用时，交易接口即使正常，进程也到不了对账和 kill 平仓。4b 让退出侧不依赖行情接口。4c 改动更小，但每次失败仍有 60 秒以上的空窗。

"任何未处理的异常都退出"作为兜底保留：只对已识别的行情请求失败做退避。

## 不在本决策内

- 账户级互斥（R20）：租约按状态目录加锁，同一账户可以在两个目录各起一个运行时。清单机制让每个目录绑定一个 scope，但不能阻止两个目录用同一个 scope。需要交易所侧或主机侧的约定，后续单独处理。
- 现金流对账（出入金、资金费、手续费）：Binance 路径没有。

## 后果

- 新增 `PaperStore`、`LimitStore` 两个端口及其 SQLite 适配器。
- 首次部署执行模式前要多一步初始化命令。
- 运行手册需要写明：换状态目录或改 scope 等于换账户身份，必须走初始化流程。

## 需要您确认

1. 子决策 1：选 1b 还是 1c。
2. 子决策 2：是否接受"日"改为 UTC 自然日。
3. 子决策 3、4：是否同意建议项。
