# ADR-0012：交易所侧止损和击穿后的平仓按交易所持仓定量；多平的止损成交不进策略账本

- 状态：**已批准**（2026-11-15，技术负责人"现在全部批准"）。原为提议稿；下面的内容是批准时的版本，实施中如有变动在本文更正并记入 `execution-log.md`。
- 日期：2026-11-15
- 关系：补完 ADR-0005 3b（3b 只覆盖急停和回撤）。依赖 ADR-0010、ADR-0011，保证正常情况下账本与交易所一致。

## 背景

`CLAUDE.md` 的 "Open exit-side gaps" 第一条：止损跟账本，不跟交易所持仓。现状【代码】：

- 有效的止损只要修订号与账本一致就保留，在读交易所持仓之前就返回（`trading/application/execution/stops.py:158-166`）。
- 需要新挂止损时：
  - 数量和入场价取自账本检查点（`stops.py:122` 的 `_position()`）；
  - 交易所为 0、或方向与账本相反，就不挂（`stops.py:172`）。
- 挂出去的止损单是整仓平仓类型（`trading/adapters/binance/adapter.py:364`，`closePosition=true`）。触发时，交易所会平掉该品种的全部持仓。
- 止损击穿后由运行时平仓。`stop_breached` 不在按交易所持仓全平的集合里（`trading/application/execution/flatten.py:30`），所以只平账本数量（`flatten.py:67`）。
- 止损触发后，它变成的订单被收编为策略的减仓单（`stops.py:199-207`），成交全部进入策略账本（`trading/application/execution/fills.py`）。
  - 交易所持仓大于账本时，账本会被推过零，变成一笔不存在的反向仓位。
  - 审计 M3 指出了这一点；它在现状下就可能发生。

## 决定

1. **账本不为 0，且交易所持仓与账本同方向**：
   - 止损覆盖交易所的全部持仓；
   - 触发价按交易所报告的入场价乘以止损距离计算；
   - 止损单类型不变（整仓平仓）。
2. **账本为 0**（交易所上的仓位全部是外来的，决定 N）：不挂策略止损。ADR-0011 负责告警并阻断入场。
3. **账本不为 0，但交易所为平、方向相反，或者请求的品种查不到**：
   - 保留已有的有效止损，不新挂，也不撤；
   - 记问题、阻断入场。
   - 查不到请求的品种时，按"未知"处理，不当作平仓（审计 M2：适配器会过滤掉数量为 0 的行，`adapter.py:195-218`，所以"空列表"和"平仓"在现在的接口上分不开）。
   - 止损只在两种情况下撤销：账本和交易所都为平；或者它被新修订号的止损取代，而新止损已经挂上。
4. **修订号**：由交易所持仓的数量和入场价派生。派生之前先按交易所的数量步长和价格精度规范化，避免文本差异导致反复撤单重挂。
5. **多平的止损成交**：收编止损订单的成交时，只按账本持仓的数量入账。多出的部分：
   - 作为外来成交写进订单库（单独记录，不进入任何所有者的检查点）；
   - 发出 `FOREIGN_FILL` 问题。
6. **击穿后的平仓按交易所持仓全平**：把 `stop_breached` 加入按交易所持仓全平的集合。重试节奏、失败告警、暂停入场都不变（ADR-0005 1b、第 12 步）。

## 状态未知与失败方向

- 交易所持仓读不出：保留已有止损，不新挂、不撤，记问题，阻断入场。
- 击穿平仓时读不出交易所持仓：不发单（没有数量就不发单），记问题，按 1b 的节奏重试。
- 止损下单的结果未知：沿用现在"查询而不重发"的处理（`stops.py` 的 unknown 状态，90 秒宽限）。
- 收编成交时账本读不出：整笔成交不入账，保持待消费状态，入场阻断。

## 备选方案

- **统一按账本**：止损改为按账本数量的普通止损单，不用整仓平仓；击穿只平账本。账本落后于交易所时保护不足。技术负责人没有选。
- **账本为 0 时也挂止损**：保护手动仓位，但触发后的成交只能全部记作外来成交，而且策略在保护不属于它的仓位。技术负责人没有选（决定 N）。

## 后果

- 同品种、同方向的手动仓位，会被策略的止损和击穿平仓一起平掉。技术负责人已接受（决定 C）。ADR-0011 会在手动仓位出现时告警。
- 策略账本只记策略自己的数量，不再因为止损多平而出现虚假仓位。
- 订单库多一类"外来成交"记录。ADR-0009 合并状态库时一起建表。

## 验收

先写测试，在改代码之前失败：
- 账本 0.1、交易所 0.15：触发价按交易所入场价；
- 账本 0、交易所 0.1：不挂止损；
- 账本 0.1、交易所为平、方向相反或查不到：已有止损不被撤销，入场被阻断；
- 交易所读失败：已有止损不被撤销；
- 数量的文本格式不同、数值相同：修订号相同，不撤单重挂；
- 账本 0.1、止损成交 0.15：账本归 0，有一条 0.05 的外来成交和 `FOREIGN_FILL` 问题；
- 击穿后交易所 0.15、账本 0.1：平 0.15；
- 击穿后读持仓失败：不发单，记问题。

另外：
- 现有退出测试的断言不变；如有改动，每一处都对应本 ADR 的一条决定，并逐条记录。
- 变异自检要覆盖：止损回到账本口径、击穿回到账本口径、读失败时撤销止损、账本为 0 时挂止损、多平部分进入账本。

## 实施更正（2026-11-15，S5b）

- 第 5 条由技术负责人推广到所有减仓单（"统一记作外来成交"）：急停、回撤、击穿平仓和止损触发的成交，超出账本持仓的部分都记作外来成交。
  - 非减仓单越过零时，只记账本那一部分，其余也记作外来成交。
  - 外来成交的所有者是 `foreign:<品种>`，成交号加后缀 `:foreign`，手续费按数量比例拆分。
  - `FOREIGN_FILL` 的后果是"只告警"。剩下的不一致由对账和 ADR-0011 的账户检查处理。
- 第 3 条"请求的品种查不到"：适配器新增 `get_position(symbol)`，平仓也返回一行数量 0，查不到返回 None，所以"平"和"未知"能分开。
- 被新修订号取代的旧止损，在新止损挂上之后同一轮立即撤掉。
- 修订号的规范化用 `Decimal.normalize()` 去掉多余的零，没有按步长取整：交易所报告的数量和价格本来就在它的步长和精度上。
