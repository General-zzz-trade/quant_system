# ADR-0010：执行模式启动时，账户里只能有策略自己的仓位和挂单

- 状态：**方向已决定**（技术负责人，2026-11-15）。实施细节如有变动，在本文更正并记入 `execution-log.md`。
- 日期：2026-11-15

## 背景

- 【实际运行结果】2026-11-15 用 `scripts.account_check` 只读核查主网账户：
  - 有一笔不是本项目开的 ETHUSDT 空单 1 ETH，11 倍全仓；
  - 仓位价值约为账户权益的 10.4 倍，没有止损单。
- 技术负责人决定：策略继续和手动交易**共用主账户**，不开子账户。
- 【代码】共用账户时，策略和手动交易会互相影响：
  - 回撤锁定和 3 倍敞口闸门都按**整个账户**的保证金余额计算（`adapter.py:204`、`runtime.py:122-124`、`exposure_gate.py:26`），手动仓位的盈亏会算进去。
  - 急停平仓和回撤平仓按交易所的实际持仓整仓平掉（迁移第 11 步），会把同品种的手动仓位一起平掉。
  - 对账发现 BTCUSDT、ETHUSDT 上有账本以外的持仓时，阻断该品种入场（`reconcile.py`）；其他品种上的手动仓位发现不了。
  - 连接账户时，程序会把 BTCUSDT、ETHUSDT 的杠杆和保证金模式**改成配置值**（`adapter.connect(configure_leverage=True)`），也就改了手动交易用的设置。

## 决定

1. **启动时只读检查整个账户。** 检查放在本地启动检查之后、对账户做任何改动之前。下面任何一项成立就拒绝启动，并逐项列出（品种、数量、订单号）：
   - 任何品种上有不属于策略账本的持仓；
   - 有不属于策略的普通挂单或条件单；
   - BTCUSDT、ETHUSDT 的杠杆或保证金模式与配置不同；
   - 账户读不出来（网络或权限错误）：按拒绝处理。
2. **程序不再修改杠杆和保证金模式。** 由人在币安上设好，启动时只核对。这与"限额只由人改"的规则一致；共用账户时，也不会悄悄改动手动交易的设置。
3. **"属于策略"的定义**：
   - 持仓：订单库里各所有者检查点的持仓之和，等于交易所的持仓；
   - 普通挂单：订单号在订单库里；
   - 条件单：客户编号在止损表里。
4. **实施细节**（2026-11-15，独立审计后更正）：
   - 没有配置保证金模式时按全仓核对：启动时的止损距离检查在这种情况下也按全仓处理。
   - **策略自己在途的东西按数量给出上下限，不再整个品种放行**。这是上下限，不是精确核算（复审发现 B）：落在范围内的外来仓位能通过启动检查，例如还挂着的 0.5 买单可以掩护 0.4 的手动多单；之后每轮对账会发现差异并阻断该品种入场。用挂单自己报告的已成交数量收紧范围，留作以后的改进。原来的写法是"某品种有没结算的策略订单就不查持仓"，审计发现它在两种情况下出错：一是范围太宽，任何大小的手动仓位都能混过去；二是会把策略自己的两种正常重启情形误判为外来。现在的核算方法：
     - 账本持仓，加上已经存下、但还没记进账本的成交（崩溃发生在两者之间）；
     - 每张没结算的策略订单，只允许交易所持仓按它的方向、最多领先它没成交的那部分数量；
     - 减仓单只能把持仓往零的方向推；数量为 0 的整仓平仓单（交易所侧止损触发后被收编的订单、按交易所持仓平仓）可以推到零；
     - 停机期间已经触发的策略止损，也可以把持仓推到零。重启后由止损同步收编它的成交，并暂停该品种入场；
     - 没有方向或数量的旧记录，不放行任何东西。
   - 普通挂单和条件单，只有同一品种的订单记录点名了它，才算策略的。
   - 对账和启动检查用同一个"账本持仓"的定义：做过成交的所有者，加上本品种策略自己的所有者。
   - 新初始化的状态目录在运行时第一次运行之前没有止损表（ADR-0009 之前）。读不到止损记录时，所有条件单都按外来处理，也不认为有止损已触发：只会多拒绝，不会少拒绝。
   - "程序里不再有设置杠杆和保证金模式的调用路径"由启动检查测试里的一条扫描保证（扫描 `trading/` 和 `runner/`），不是单独的架构测试。
   - **拒绝启动的代价**：被拒绝时运行时完全不运行。策略自己持仓的止损不会补挂，待执行的急停平仓、回撤平仓不会执行，挂着的限价入场单也不会按时撤掉。所以拒绝之后，要由人在币安上核对策略自己的仓位和挂单。运行手册写明了这一点。
5. **外来仓位由人在币安上处理**，不要用 `manual position` 收编。收编会把手动仓位变成策略仓位，之后由策略的止损、急停和回撤来管理。运行手册写明这一点。

## 不在本次决定之内（已知缺口，M5 之前再定）

- 运行中才出现的外来仓位或挂单：
  - BTCUSDT、ETHUSDT 上的，每轮对账都会发现，并阻断该品种入场；
  - 其他品种上的发现不了，但它们的盈亏会进回撤锁定。
  - 运行中要不要也检查整个账户，M5 之前再问。
- 模拟盘不连账户，不受影响。

## 验收

- 测试先写，在改代码之前对旧代码失败：
  - 外来持仓（策略品种、其他品种）、外来挂单、外来条件单、杠杆不符、保证金模式不符、账户读不出，各自拒绝启动，并且没有发出任何写请求；
  - 账户与账本一致、设置与配置一致时，正常启动。
- 程序里不再有设置杠杆和保证金模式的调用路径；架构测试固定这一点。
- 现有的运行时测试、研究模拟指纹测试、模拟盘与研究逐笔一致的测试，断言不变并全部通过。
