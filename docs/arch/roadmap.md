## 2. 目标与完成标准

改造完成时，下面六条都能用命令或测试检查：

1. **新结构完全接管**：加载运行时后，内存里没有任何旧包和 Rust 扩展。
2. **退出可靠**：急停或回撤触发后，仓位在可预期的时间内归零；失败会重试并告警。
3. **缺陷清零**：已知缺陷测试为 0，或剩下的每一条都有技术负责人明确接受的理由。
4. **仓库干净**：每个模块要么在用，要么属于明确冻结的范围。
5. **经过运行检验**：测试网上连续运行数周，对账无差异。
6. **可以交接**：只读 `docs/arch/` 和测试，就能说清每个模块的职责和每条不变量由哪个测试保证。

## 4. 工作方式

这些规则今天已经在执行，写在这里作为约定：

- **绞杀式**：每一步系统都能运行；旧位置留转发，直到 M4 统一删除。
- **先测试后实现**：先写测试固定现状或描述目标行为，再改代码。2026-11-14 有一次顺序颠倒，随后被审计查出缺陷。
- **证据**：每步有注入缺陷自检和新旧行为对比；改行为的步骤，每处断言变更对应一条已批准的决定。
- **一个步骤一个 PR**，内含多次小提交，每次少于 400 行手写。大步骤可以在一个能独立验证的位置先合并一次。
- **不等待**：代码测完就开 PR；自检并行跑，每个注入缺陷只配能抓到它的那一个测试；全量测试只在 CI 跑。
- **不中途换线**：一个里程碑做完之前，不主动开新的研究线。技术负责人提出的除外。
- **遇到取舍就问**，不自行假设。
