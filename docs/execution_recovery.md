# 成交驱动与恢复验收（2026-11-02）

本批针对 OKX 的执行与恢复链路。所有验证使用本地假交易所，不需要资金、VPS、API 密钥，不连接真实交易账户。

## 已实现的行为

- 策略的目标信号、待确认订单、实际仓位分开管理。生成开仓、加仓、平仓意图不再改实际数量或入场均价；实际成交才更新。平仓请求未完成时保留剩余仓位，反向信号先平仓，后续决策重新通过风控再开仓。
- 4h runner 继续只发布方向，不附加执行桥，也不认领 1h 的交易仓位。
- 订单提交前持久化稳定客户单号、方向、数量、策略归属和父事件。超时只查询原单，不自动重新发送。
- 成交表兼作 outbox：成交唯一键与待处理事实是同一条数据库记录，不存在“已写成交但漏写待处理记录”的窗口。
- 消费成交时，Rust 状态快照、策略仓位/已实现价差盈亏/分币种费用、策略执行状态与消费回执在同一 SQLite 事务提交。提交失败恢复内存状态；进程死亡后从已提交快照恢复，重放未确认记录。
- 行情决策后刷新已有消费快照中的追踪峰值、持仓时间和止损冷却状态。重启时把 bar 计数映射到当前预热时钟，不把新进程的预热 bar 数当成新的持仓时长。
- 启动和运行期间核对订单、挂单、仓位及待处理成交。未知仓位、未知挂单、未决订单、无效/失败响应和对冲持仓均阻止开仓，输出具体原因；不再把账户仓位直接覆盖成策略持仓。
- 同机同数据库目录、同账户 scope 只允许一个 OKX 执行进程。进程内可运行多个 runner。跨主机单写者保证和分布式额度预留不在本批范围内。
- CI 只运行检查；Deploy 改为手动触发且默认不确认，避免开发提交自动重启服务。

## 无依赖检查

```bash
python scripts/check_local_safety.py
```

包含真实子进程强制退出、迁移旧表结构、超时后恢复、部分成交、重复成交、提交失败回滚、单写者锁等场景。脚本禁止网络，使用临时数据库。

安装完整开发环境并构建 Rust 扩展后：

```bash
python -m pytest tests/unit/execution/adapters/okx/ tests/unit/decision/ tests/unit/engine/
```

`test_durable_recovery.py` 使用实际 Rust pipeline、策略和执行边界，验证：

| 故障条件 | 预期行为 | 证据 |
|---|---|---|
| 成交已落盘，尚未进入引擎时重启 | 恢复并处理该成交，不重复提交订单 | 账本待处理数、Rust 持仓、策略持仓、实际提交调用次数 |
| 0.4 部分成交后重启，再到达 0.6 成交 | 持仓从 0.4 变为 1.0，按成交价格算均价 | 持仓、均价、待处理订单与成交唯一键 |
| 处理成交途中异常 | 内存状态回滚，待处理记录保留，重试只入账一次 | 事务前后 Rust/Python 状态与回执 |
| 重复投递已处理成交 | 数量、盈亏、费用不重复增加 | 前后持久化快照完全相同 |
| 订单被拒或部分平仓 | 拒单不改变持仓；部分平仓保留余仓 | 策略状态、待确认订单集合 |
| 仓位不符、外部挂单、查询超时 | 禁止新开仓，不虚构成交纠正仓位 | 开仓就绪标记、查询差异、订单生成数量 |
| 行情推进了追踪峰值后重启 | 峰值和已持仓 bar 数恢复 | 新旧执行状态对比 |

## 数据库和升级

继续使用 `ORDER_JOURNAL_PATH`，默认 `data/runtime/orders.sqlite`；`RISK_SCOPE` 必须稳定。
新表为 `execution_fills`、`execution_consumers`，原 `submissions` 通过新增字段升级。消费快照按账户 scope 和策略 owner 隔离。

升级前停止执行进程，使用 SQLite backup API 做一致性备份（包括 WAL 中的已提交内容）。旧记录没有方向、数量、父事件时，系统保留锁并报告，不能靠删除数据库或改 scope 解锁。账户存在旧仓位时，先以只读方式核对交易所订单和成交，补齐经审核的迁移方案后再运行；本批不提供猜测归属的自动导入。

回滚代码不能代替回滚运行状态：新版写过数据库后，不应直接启动不认识新消费回执的旧执行程序。先停止执行，保留数据库备份，核对真实账户状态，再决定恢复方案。

## 明确限制

1. 这是故障行为验收，不是盈利证明，也不是实盘上线批准。
2. 交易所历史接口当前每单读取最近最多 100 条成交，超出窗口、历史缺失或响应不一致时保持锁定；完整分页、长期归档恢复仍待开发。
3. 旧订单、人工交易、强平/ADL、对冲模式需要独立对账流程。当前自动恢复覆盖本版本记录且能获取完整成交事实的订单。
4. 分币种费用保留交易所符号，价差已实现盈亏独立记录；尚未完成资金费、入出金、币种换算和账户总权益的完整账务对账。Rust 账户视图与辅助 PnL 监控不是财务总账。
5. 交易账本与回执具有事务去重；TCA 日志、监控回调等辅助输出不保证恰好一次，不能据其条数代替成交账本验收。
6. Bybit/Binance 尚未接入本批持久化消费与启动恢复流程，不能由 OKX 测试通过推断它们可部署。
7. 本机单写者锁要求账户使用同一持久目录；改目录、多主机或多个交易程序仍需统一协调和账户级额度预留。
